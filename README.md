## QA 통합 대시보드 — AI 체크리스트 자동 생성 · 데이터 검색 · 이슈 분석

## 1. 사용 도구 및 기술

* **언어 및 프레임워크** : Python + Streamlit
* **AI / LLM** : Ollama (로컬 LLM), BM25 기반 RAG
* **외부 API** : GitLab API
* **데이터 처리** : pandas, pdfplumber
* **실행 환경** : 로컬 서버 (외부 서버 의존 없음)

## 2. 프로젝트 구조

Project  
├── dashboard.py  
├── chatbot.py  
├── search.py  
├── data/  
└── .env  

| 파일명 | 역할 및 내용 |
| ------ | ------ |
| dashboard.py | Streamlit 기반 UI, 페이지 라우팅, 세션 상태 관리 |
| chatbot.py | RAG 인덱스(BM25), GitLab 이슈 수집, LLM 챗봇 로직 |
| search.py | CSV 테이블 로드, AI 키워드 확장 검색, 데이터 검증, 체크리스트 생성 |
| data/ | QA 데이터 CSV 테이블 저장 폴더 |
| .env | GitLab API 토큰 및 환경 변수 설정 |

## 3. 주요 기능 및 실행 흐름

### 3-1. 체크리스트 자동 생성
```
[GitLab 이슈 번호 입력 (선택)]
    ↓
[GitLab API로 이슈 본문 · 코멘트 자동 수집]
    ↓
[추가 내용 직접 입력 (선택)]
    ↓
[LLM이 QA 체크리스트 Markdown 테이블 형태로 생성]
    ↓
[Markdown → TSV 변환 → Google Sheets 붙여넣기 버튼]
```

### 3-2. AI 데이터 검증
```
[검증 조건 입력 (텍스트 or 파일 업로드: CSV · XLSX · PDF · TXT)]
    ↓
[테이블 직접 선택 or AI가 관련 테이블 자동 탐색]
    ↓
  ├─ CSV / XLSX 파일 조건
  │    programmatic_validate() → 행 단위 실데이터 비교
  │    불일치 발생 시 → AI 불일치 원인 추가 분석
  │
  └─ 텍스트 조건
       ai_validate_data() → AI가 조건 기반 검증 후 결과 출력
```

### 3-3. RAG 챗봇
```
[모드 선택: 자유대화 / 데이터 참조]
    ↓ (데이터 참조 모드)
[테이블 or GitLab 이슈 로드 → BM25 인덱싱]
    ↓
[자연어 질문 입력]
    ↓
  ├─ 시간 기반 쿼리 ("1시간 전", "최근", "오늘" 등)
  │    BM25 우회 → 전체 GitLab 청크를 등록일시 기준 최신순 정렬
  │
  └─ 일반 쿼리
       BM25 키워드 검색 → 관련 청크 추출
    ↓
[LLM 답변 생성 + 출처 표시]
```

### 3-4. 테이블 검색 · 뷰어
```
[검색어 입력]
    ↓
  ├─ AI 테이블 선별 ON
  │    LLM이 키워드 확장 + 관련 테이블 자동 선별 후 검색
  │
  └─ AI 테이블 선별 OFF
       키워드 토큰 직접 추출 → 전체 테이블 검색
    ↓
[테이블별 결과 출력 + CSV 다운로드]
```

## 4. 결과물 검토 및 보완

### 1. 개발 중 발생한 문제 및 원인

**1-1. 시간 기반 쿼리 오작동**
- "1시간 전 등록된 이슈"처럼 시간 조건이 포함된 질문은 BM25 키워드 매칭으로는 정확도가 낮아 관련 없는 이슈가 반환되는 문제 발생
- GitLab 타임스탬프가 UTC 기준으로 저장되어 있어 LLM이 현재 시각과 비교 시 오차 발생

**1-2. GitLab 재로드 시 청크 중복 누적**
- GitLab 이슈를 재로드할 때마다 기존 청크 위에 새 청크가 추가되어 동일 이슈가 중복으로 검색에 반영되는 문제 발생

**1-3. LLM 모델 호출 성능 이슈**
- Streamlit은 페이지 리렌더링 시 전체 코드를 재실행하므로, 매 렌더링마다 `ollama.list()` API를 호출해 불필요한 지연 발생

### 2. 수정 · 보완한 내용 및 이유

**2-1. 시간 쿼리 감지 및 BM25 우회**
- 정규식으로 시간 관련 표현("한시간", "두시간", "오늘", "최근" 등)을 감지하여 BM25를 우회
- 전체 GitLab 청크를 `등록일시` 기준 최신순 정렬 후 LLM에 전달
- 시스템 프롬프트에 현재 KST 시각과 UTC→KST 변환 지시를 명시하여 시간 비교 정확도 향상

**2-2. GitLab 청크 선택 제거 메서드 추가**
- `clear_gitlab()` 메서드를 구현해 GitLab 청크만 선택 삭제 후 재인덱싱하도록 처리
- 테이블 청크는 유지되어 재로드 시 불필요한 테이블 재처리 방지

**2-3. 세션 상태 캐싱으로 성능 최적화**
- CSV 테이블, LLM 모델, RAG 인덱스를 `st.session_state`에 캐싱
- 페이지 이동 및 리렌더링 시 데이터 유지, 불필요한 API 호출 제거

**2-4. 데이터 검증 이중 전략 적용**
- 텍스트 조건 → AI 자연어 검증 / 파일 조건(CSV·XLSX) → 프로그래밍 방식 행 단위 비교로 구분
- 정성·정량 검증을 모두 커버하도록 설계

### 3. 실무 관점에서 추가 가능한 케이스

**3-1. 체크리스트 관련**
- 기획서 변경 전후 버전 자동 비교 및 항목 차분 추출
- 체크리스트 완료 여부를 GitLab 이슈에 자동 코멘트로 업데이트

**3-2. 챗봇 관련**
- 답변 생성에 사용된 근거 청크 하이라이팅
- 멀티 LLM 지원 (Ollama 외 OpenAI · Claude API 선택 가능)

**3-3. 데이터 검증 관련**
- 다중 테이블 간 외래키 정합성 자동 검증
- 검증 결과 리포트 자동 생성 및 GitLab 이슈 첨부
