## QA 통합 대시보드 — AI 체크리스트 자동 생성 · 데이터 검색 · 이슈 분석

## 1. 개요
- 게임 QA 업무(데이터 검색·검증·체크리스트 작성·팀 문서 관리)를 한 화면에서 처리하는 Streamlit 기반 웹 대시보드입니다.
- 로컬 LLM(Ollama)을 연동해 외부 API 비용·보안 이슈 없이 사내 환경에서 완전히 동작하도록 설계했습니다.
- `dashboard.py`(UI) · `search.py`(검색·검증·GitLab 연동) · `chatbot.py`(질문과 관련된 데이터를 먼저 찾아 답변 근거로 쓰는 RAG 방식 챗봇 엔진) 세 모듈로 구성된 하나의 통합 툴입니다.
- GitLab Token, CSV 데이터 경로 등 민감 정보는 `.env` 또는 예시값으로 분리되어 있으며, 실제 게임 데이터·사내 문서는 저장소에 포함되어 있지 않습니다.
- 개발 과정에서 Claude Code를 페어 프로그래밍 도구로 활용했습니다 (기능 설계·구현·리팩토링 보조).

## 2. 주요 기능

### QA 도구
- **테이블 검색**: CSV로 관리되는 게임 데이터 테이블을 키워드로 즉시 검색, AI가 검색어와 관련된 테이블만 자동으로 선별해 범위를 좁혀줌
- **데이터 검증**: 기획 변경 조건(텍스트 또는 CSV/XLSX/PDF 파일)을 입력하면 실제 데이터와 자동 대조 — 값이 일치하는 CSV/XLSX는 프로그래밍 방식으로 정확히 비교, 서술형 조건은 AI가 판정
- **테이블 뷰어**: 전체 테이블 목록·컬럼 정보·행 검색을 지원하는 데이터 탐색 화면, CSV 다운로드 지원
- **체크리스트 생성**: GitLab 이슈 번호만 입력하면 본문·코멘트를 자동 수집해 QA 체크리스트(Markdown Table)를 생성, Google Sheets에 바로 붙여넣을 수 있는 TSV 복사 기능 포함

### AI 챗봇
- **자유 대화 모드**: 별도 데이터 없이 바로 대화 가능한 범용 어시스턴트
- **데이터 참조(RAG) 모드**: 로드된 CSV 테이블·GitLab 이슈 중 질문과 관련된 내용만 검색해서 답변 재료로 붙여준 뒤 답변하게 하는 방식. 근거 없는 답변(환각)이 잘 나오지 않고, 어떤 데이터를 참고했는지 출처도 항상 함께 보여줌
- **시간 기반 질의 처리**: "최근", "오늘", "3시간 전" 같은 질문을 감지해 GitLab 이슈를 등록일시 기준으로 정렬해 응답

### 문서 관리
- 홈/팀 구조/명령어 목록/테이블 설명 등 팀 공유 문서를 대시보드 안에서 바로 편집·저장 (Markdown 기반)

## 3. 기술적으로 신경 쓴 부분

- **환각 방지 프롬프트 설계**: 데이터 검증·RAG 응답 모두 "실제값을 먼저 인용하고, 조건과 비교한 다음, 마지막 줄에 판정을 적으라"는 순서를 지키도록 강제하고, 참고 데이터에 없는 내용은 만들어내지 못하도록 시스템 프롬프트에 규칙을 명확히 적어뒀습니다
- **검색 엔진 직접 구현**: 검색어와 문서의 연관도를 점수로 계산하는 BM25 알고리즘을 외부 라이브러리 없이 `chatbot.py`에 직접 구현. CSV는 행 단위로, GitLab 이슈는 건 단위로 검색 가능한 조각(청크)으로 나눠 인덱싱
- **다중 인코딩 CSV 로더**: 한글 CSV의 흔한 인코딩 문제(cp949/euc-kr/utf-8-sig 혼재)를 `chardet` 자동 감지 + 순차 폴백으로 안전하게 처리
- **꼼꼼한 검증 로직**: 조건 파일 비교 시 빈 값·빈 컬럼은 검사 대상에서 자동 제외해 거짓 불일치를 방지하고, ID·CID 번호를 정규식으로 뽑아내 비교할 행을 좁혀줌
- **AI 테이블 자동 선별 + 검색 우선순위 정렬**: 검색 결과를 셀 완전 일치, 부분 일치, AI 추천 테이블, 나머지 순으로 정렬해서 관련성 높은 데이터가 먼저 보이도록 구성

## 4. 실행 흐름

```
1. 대시보드 실행 → CSV 테이블 자동 로드, 사용 가능한 Ollama 모델 감지
2. [QA 도구] 탭에서 검색/검증/뷰어 기능 사용
   └── 검증 조건 입력 → AI가 관련 테이블 자동 탐색 또는 직접 테이블 지정
3. [AI 챗봇] 탭에서 테이블/GitLab 이슈를 인덱싱한 뒤 RAG 기반 질의응답
4. [체크리스트 생성] 탭에서 GitLab 이슈 번호 입력 → 본문·코멘트 자동 수집 → AI가 체크리스트 생성
5. 문서 페이지(홈/팀 구조/명령어 목록/테이블 설명)를 통해 팀 공유 자료 관리
```

## 6. 설치 및 실행

```bash
pip install streamlit pandas chardet ollama requests python-dotenv pdfplumber openpyxl
streamlit run dashboard.py
```

- `dashboard.py`는 같은 폴더의 `search.py`, `chatbot.py`와 함께 있어야 동작합니다.
- Ollama가 로컬에 설치되어 실행 중이어야 AI 기능(검증/체크리스트/챗봇)을 사용할 수 있습니다.
- GitLab 연동 기능은 `.env.example`을 참고해 `.env`에 `GITLAB_URL` / `GITLAB_TOKEN` / `GITLAB_PROJECT`를 설정해야 동작합니다.
- CSV 데이터는 `data/csv` 폴더에 넣으면 자동으로 로드됩니다 (없어도 앱은 정상 실행됨).

## 8. 결과물 검토 및 보완

### 8-1. 개발 중 발생한 문제 및 원인

시간 조건이 들어간 질문(예: "1시간 전 등록된 이슈")은 키워드 검색만으로는 정확한 결과를 찾기 어려웠습니다. 게다가 GitLab 이슈의 시간 데이터는 UTC 기준으로 저장되는데, AI가 현재 시각과 그냥 비교하면 9시간 오차가 생기는 문제도 있었습니다.

GitLab 이슈를 다시 불러올 때마다 기존 인덱스 위에 새 데이터가 그대로 쌓여서, 같은 이슈가 검색 결과에 중복으로 나오는 문제도 있었습니다.

또한 Streamlit은 화면이 바뀔 때마다 스크립트 전체를 처음부터 다시 실행하는 구조라, 별도 처리 없이 두면 매번 설치된 Ollama 모델 목록을 다시 조회하는 등 불필요한 작업이 반복됐습니다.

### 8-2. 수정·보완한 내용 및 이유

- **시간 관련 질문 자동 감지**: "한 시간", "두 시간", "오늘", "최근" 같은 시간 표현을 정규식으로 감지하면, 일반 키워드 검색 대신 GitLab 데이터 전체를 등록일시 기준 최신순으로 정렬해 AI에 전달합니다. 시스템 프롬프트에도 KST(+9시간)로 변환해 비교하라고 명시해 오차를 없앴습니다.
- **GitLab 데이터만 선택적으로 삭제**: 재로드할 때 `clear_gitlab()`으로 GitLab 데이터만 지우고 테이블 데이터는 그대로 둬서, 중복 없이 최신 이슈만 다시 인덱싱되게 했습니다.
- **세션 상태를 이용한 캐싱**: CSV 테이블, Ollama 모델 정보, 검색 인덱스를 `st.session_state`에 저장해서 화면이 다시 그려져도 매번 다시 계산하지 않도록 했습니다. 모델 조회 자체에도 60초짜리 캐시를 둬서 응답 속도를 개선했습니다.
- **데이터 검증 방식 이중화**: 텍스트로 적은 조건은 AI가 판단하고, CSV/XLSX로 첨부한 조건은 실제 데이터와 프로그래밍 방식으로 하나하나 비교합니다. 사람이 판단해야 하는 경우와 숫자를 정확히 맞춰봐야 하는 경우를 둘 다 다룰 수 있습니다.

### 8-3. 실무 관점에서 추가로 고려해볼 개선 아이디어

- **체크리스트**: 기획서 변경 전/후 버전 자동 비교로 달라진 항목만 추출, 체크리스트 완료 여부를 GitLab 이슈에 댓글로 자동 등록
- **챗봇**: 답변 근거로 사용한 데이터 항목을 UI에서 강조 표시, Ollama 외 다른 모델(OpenAI, Claude 등)도 선택할 수 있도록 확장
- **데이터 검증**: 여러 테이블에 걸쳐 연결된 데이터의 정합성 자동 검사, 검증 결과를 보고서 형태로 자동 생성해 GitLab 이슈에 첨부
